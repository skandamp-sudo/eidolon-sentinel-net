# SIH-F6 — analyst operations and final SIH hardening

F6 adds read-only investigation and assurance views over existing persisted evidence. The detector pipeline, scientific source, thresholds and models are unchanged. The final scientific candidate remains CANDIDATE, SUITABLE FOR OPERATOR REVIEW, NOT APPROVED and NOT PUBLISHED.

1. **Correlation architecture.** On-demand authenticated SQLite snapshot → allowlisted projection → deterministic correlation/timeline → validated canonical JSON. No detection-pipeline hook, new inference, new protocol parsing or persistent graph. See `sih-f6-architecture.md`.
2. **Correlation semantics.** Within-event evidence sources plus conservative same-flow neighbors. Cross-event membership requires exact flow ID, ordered endpoints, protocol, LIVE/REPLAY source identity and ±300 seconds of recorded event timestamp. Shared IP/fingerprint alone is insufficient. Source types are not statistically independent signals. Scores, severity and existing risk are unchanged; no combined probability.
3. **Bounded state.** Four active response leases per API process, 32 candidate events, 256 evidence references, 512 timeline items, 128 KiB stored-field limits and 1 MiB export. Five-second read deadline, 15-second send lease, 20-second browser operation timeout. No cached graph; response completion/cancellation expires active state. Retention remains authoritative. Multi-worker deployments multiply admission bounds.
4. **Investigation timeline.** Actual retained DNS/TLS/QUIC timestamps, evidence window ends and record timestamps only. Capture, processing and unspecified historical event clocks stay distinct. No missing handshake, flow or detection step is synthesized. REPLAY remains RECORDED TRAFFIC REPLAY.
5. **Forensic export.** Authenticated existing-event JSON export; fixed application filename, version 1.0.0 envelope, event/model/schema provenance, existing ML/anomaly/F3/F4/F5/qualified ATT&CK fields, correlation, timeline and limitations. Risk is included only if recorded. Arbitrary metadata and unselected supporting context are omitted explicitly. See `sih-f6-export-api.md` and `sih-f6-export-schema.json`.
6. **Integrity/hash semantics.** SHA-256 over exact canonical response bytes, exposed in a header and verified by the browser before saving. Unchanged snapshots are byte-deterministic; mutation changes the digest. This is not a digital signature, authorship proof, trusted timestamp or complete legal chain of custody.
7. **Export security.** Existing API-key middleware; bounded identifier pattern; parameterized SQL; no arbitrary file access or client-selected paths; explicit field allowlist; no-store/nosniff; fixed-size response and admission bounds; bounded download reader; no HTML export renderer. No configuration credentials, registry paths, raw TLS/DNS payload fields, model serialization or stack-trace fields are exported. Authorized endpoint/DNS/SNI metadata still requires analyst privacy handling.
8. **Readiness/assurance.** Sensor page shows actual lifecycle, database SELECT 1, loaded model identity (or UNAVAILABLE), feature schema, and browser WebSocket state. Passive/no-active/no-decryption/runtime-frozen properties are qualified software properties. Native real-interface and physical diode validation remain NOT VERIFIED. Polling avoids overlapping requests and clears stale identity when the API changes/fails.
9. **Scientific summary.** Packaged, hash-linked FINAL-SCIENCE-RESTART-2 summary; exact values regression-tested. XGBoost accuracy 0.7594399223, macro-F1 0.2675121989, benign→malicious FPR 276/267851, C2 recall 0, DDoS recall 0.2667833206, Isolation Forest ROC-AUC 0.8184012477. COMPLETE refers only to the documented software scope. PARTIAL/NOT VERIFIED identify reflection/spoofing attribution, statistical detector validation, n-grams, JA4, hardware and operational guarantees. This is traceability, not independent certification.
